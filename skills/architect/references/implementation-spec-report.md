# Implementation Spec 单页报告

使用 `archify`skill  的 `explainer` 模式，以 `workflow` 主图展示 Module 的工作过程，复杂类型契约补充 `class` 图。页首概括 Module 的核心设计结论，修订时说明本次变化。

## 工作过程

按以下方式与思路绘图：

- **阶段列**：从左到右排列“输入／触发 → 逻辑执行 → 输出／外部效果”，用 `phases` 表达。
- **职责泳道**：从上到下排列 Spec 声明的内部封装单元、职责分区或运行边界，用 `lanes` 表达。外部参与方与模块内部职责分开。
- **节点**：放在承担该动作或判断的泳道内。标明关键输入、读取或更新的状态，以及返回值、事件、写入或呈现结果。
- **连线**：表达执行顺序、跨单元调用与返回，标注分支条件和关键数据。按文档保留异步交接、失败与恢复路径。

覆盖 Spec 定义的入口与 Feature 行为，突出正常主路径。独立流程可分图展示，不将互不相干的行为串成先后关系。阶段与泳道用于组织已有设计，不为填满网格补造步骤或封装单元。

## 类型契约

涉及复杂数据结构、接口契约或继承与组合关系时，补充 `class` 图。展示理解工作过程所需的类型、关键字段与方法，区分依赖、关联、继承、实现和组合关系，沿用 Spec 中的名称与签名。

## 单页组织

通过 `explainer` 整合 Workflow 与可选 Class 图，文字补充设计依据与变更影响。
