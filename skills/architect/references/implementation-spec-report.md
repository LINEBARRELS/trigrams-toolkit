# Implementation Spec 单页报告

遵循[报告通用指引](report-guide.md)，按行为形状选用 `sequence` 与 `flow` 展示 Module 的功能与运行流程；涉及状态流转、接口契约、数据模型或复杂类型契约时，按需补充 `state`、`api`、`er` 或 `class` 图。页首概括 Module 的核心设计结论，修订时说明本次变化。

## 模块功能与流程

按以下方式和思路绘制图表，覆盖 Spec 定义的生命周期、驱动机制与主体功能流程：

- **跨单元协作与异步交接**：使用 `sequence`（可加 `num` 编号）。用 `participants` 区分外部参与方与 Spec 声明的内部封装单元或运行边界，用 `== 阶段 ==` 分隔“输入／触发”、“逻辑执行”、“输出／外部效果”等模块运行流程 phase，用实线、虚线与 `note` 标明调用顺序、返回、异步交接及关键数据或状态更新。
- **分支判断与失败恢复**：使用 `flow`（宜用 `flow LR`）。用 `group` 标明内部职责边界，用菱形节点表达分支条件，用圆柱节点标明读取或更新的状态与存储，并按文档保留失败与恢复路径。
- **独立流程拆分**：互不相干的独立功能流或复杂子流程分图展示，不强行串成先后关系。

修订时在 `flow`、`state`、`er`、`api` 中使用变更标记标出变化点。不为填满版面补造文档未定义的步骤或封装单元。

## 核心契约与补充视图

- **代码契约与约束**：直接引用或整理 Spec 中的精简代码声明代码块（修订时可用 `diff` 块展示契约变更），配合简短要点标明数据所有权、关键不变量与失败语义。
- **类型关系视图**：涉及多类型继承、实现、组合或依赖关系时，补充 `class` 图，沿用 Spec 代码声明中的精确名称与签名。
- **状态与协议视图**：Spec 明确定义了对象生命周期状态机时，可补充 `state` 图；定义了 HTTP／RPC 接口或持久化实体结构时，可补充 `api` 或 `er` 图。
