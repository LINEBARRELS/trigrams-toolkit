# 将源码声明关联到 Plan 的 Stub

依据 Plan 进行开发代码时，应在关键声明处维护包含 Plan 与 Stub 标识的注释，使项目长期演进中可直接从源码追溯设计来源与变更上下文。

源码标识与注释维护应遵循以下要求：
- **长期溯源标识：** 为本次新增或主导变更的类、函数、独立常量、枚举及工具函数声明添加 `@plan-stub {plan-name}-{stub-id}` 注释（`plan-name` 取 Plan 目录名，`stub-id` 取对应 Stub 编号，如 `@plan-stub inventory-v2-S01`）；同一声明归属多个 Stub 时分别标识。该标识随代码长期保留，供后续检索与溯源。
- **待实现注释说明：** 若当前某部分的开发仅涉及框架搭建或类型声明，可先在待实现处简要注明预期步骤、输入输出约束与边界条件（如 `// TODO: 读取库存 -> 校验可用量 -> 原子扣减；不足返回约定失败结果`）。
- **完工清理：** 完整的代码逻辑开发完成后保留 `@plan-stub` 溯源标识，同时清除已失效的伪代码与待办注释，并按最终实现进行简短的注释说明。
