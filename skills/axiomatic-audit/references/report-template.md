# 可视化报告模板与输出约定

本约定指导使用全局 `answer-me-with-html` Skill 生成公理设计审计报告。

## 1. 输出路径与命令约定

- 成品目录：目标项目根 `.tmp/axiomatic-audit/`。
- 命名格式：`<YYYYMMDD-HHMM>-<scope>.html`（例如 `20261127-1430-module.html`；多层汇总用 `full`）。
- 渲染参数：应传入 `--no-open` 与 `-o "<项目根>/.tmp/axiomatic-audit/<文件名>.html"`，避免弹出浏览器打断操作，并确保报告保存在目标项目工作区内。
- 中间数据：求解脚本的输入 JSON（`<scope>-input.json`）、结果 JSON（`<scope>-result.json`）与 Markdown 矩阵（`<scope>-matrix.md`）一并留在 `.tmp/axiomatic-audit/` 供复核。

## 2. 报告版面结构（`template: sheet`, `cols: 3`）

使用 `answer-me-with-html` 的 `sheet` 模板，控制在 5 到 6 个面板内，先给结论再给证据。每句说明遵守简洁原则，避免渲染触发 STE 告警。

| 面板 | 建议标题与跨度 | 必备内容 |
| --- | --- | --- |
| Lead | （文首 1 到 2 句） | 本次审计层级、最终评级（非耦合 / 准耦合 / 耦合）与最突出风险 |
| **A** | `总判与双视图对比` | `callout` 标明最终评级；对比表列出“仅显式 `D` 视图”与“完整 `D + C` 视图”的评级、边数与耦合环数 |
| **B** | `重排后的设计矩阵` `{span=2}` | 直接贴入 `matrix_solver.py` 重排后的表格；注明图例（`●` 自身、`D` 显式、`C` 暗叉、`!X` 右上角越界耦合）与推荐调参/依赖序 |
| **C** | `耦合环与依赖结构` | 用 `flow` 图展示主要依赖方向与强连通耦合环（SCC），用 `*` 高亮成环节点或瓶颈 DP |
| **D** | `源码证据与暗叉清单` `{span=2}` | 表格列出全部右上角越界边与关键暗叉 `C`，含 `FR`、`DP`、类型、精确 `path:line` 与一句说明 |
| **E** | `ARD 漂移与信息公理` | 列出幻影节点（ARD 有而代码无）、野生节点（代码有而 ARD 无）、欠定/冗余列与冗余转发层信号 |
| **F** | `破环与重构建议` `{span=3}` | 按影响优先级编号列出具体解耦动作，每条写明目标模块/文件、推荐手法与预期消除的耦合边 |

## 3. 绘图与行文约束

- 矩阵顺序应完全采用 `matrix_solver.py` 输出的 `ordered_frs` 与 `ordered_dps`，不在写报告时手动改排。
- 如果 `full_view.classification` 为 `uncoupled` 或 `decoupled`（无耦合环），Panel C 改为展示合法的依赖拓扑序，Panel D 列出关键跨模块显式依赖抽样与零耦合环说明，不虚构问题。
- 渲染若出现 STE 告警，修正告警行后用同一 `-o` 路径原地重渲染，直至无告警或达到重试上限。
