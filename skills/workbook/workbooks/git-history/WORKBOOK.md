# Git 关键变更整理

## 适用与输入

接收目标项目根、Git 仓库、目标分支和提交起点。首次运行明确起点；后续运行沿用该分支上次成功覆盖的终点。频率与运行宿主由调用方配置，采用本 workbook 本身不创建定时任务。

输出位于目标项目根的 `docs/knowledge/retrospectives/`。按终点完整提交 SHA 命名记录，正文保存仓库标识、分支、起止 SHA、生成日期和完整覆盖标记。仅为续办核对本分支记录的范围与状态；历史原因或跨记录影响分析通过 `why`、`effect` 取得。

## 必要工作流程

1. 解析目标分支的完整提交 SHA 作为本次终点，核对起点属于该终点历史（起点不含、终点包含）。首次覆盖根提交时显式选择从根提交开始的完整范围。
2. 用 `git log` 枚举区间内的提交、作者时间、说明和受影响路径，再用 `git show` 或区间 diff 核对关键变化。按完整 SHA 去重并按变更主题整理。
3. 记录影响后续理解的行为、接口、兼容性和故障修复，写明受影响模块、前后变化、提交背景与可定位的验证结果，附完整提交 SHA 和路径。动笔编辑文档前使用 doc-polish。
4. 核对来源与范围后写入记录，成功后标记完整覆盖。无值得摘要的变化时只保存覆盖范围与判断依据；仅改动本输出目录的提交不生成新的经验条目。

## Task 切分与交接

一次独立整理可由一个 general Task 完成，无需预先安装框架。范围过大时按连续提交区间拆分，各段交付已覆盖范围与下一段起点。后段消费前段完整覆盖结果时声明 `dependsOn`。

## 产出与验收

核对每条关键变化能定位到真实提交与路径，背景和验证结论有证据，声明覆盖范围内的提交均已检查。重复执行不增加重复条目；失败或中断不推进覆盖终点。只覆盖部分提交时报告实际范围与剩余缺项。

交付记录路径、起止 SHA、覆盖状态及未知项。

## 工作约束

- 全部 Git 操作只读，不切换分支或修改工作区；同一仓库和分支的整理任务串行运行。
- 同一仓库、分支、起止 SHA 复用同一记录，补齐中断内容后再标记完整覆盖；无新增提交时不写入，部分生成或写入失败保留原起点。
- 终点文件已存在但范围不同，或分支历史改写导致原终点不可达时，报告原范围与当前终点，不覆盖无关记录。
