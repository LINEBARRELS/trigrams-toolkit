# 技术说明撰写

## 适用与输入

输入目标受众、使用场景、可靠事实、已有正文和完成条件。材料不足时记录信息缺口与待确认项。

## 必要工作流程

明确读者目标与上下文，核对事实来源，按操作顺序或概念依赖安排文稿结构、术语、示例与操作步骤。动笔编辑文档前使用 doc-polish，提供用途和关键事实。

## Task 切分与交接

同一受众与用途的完整文稿由一个 general Task 交付。其他执行者需提前采用文稿结构与术语时，将结构、术语和验收约定定义为 Stub，拆分为安装与装填 Task；完整文稿依赖使用 `dependsOn`。

## 产出与验收

核对事实来源、引用可达性、术语一致性与操作可行性。命令与流程采用代表性场景验证并记录环境约束，未验证项单独列明。

交付文稿、示例、验证证据及限制。独立且长期引用的正式文稿交接 Artifact 登记信息，草稿与核验记录归 Task 证据。
