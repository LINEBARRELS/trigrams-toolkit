# Agile 开发 subagent 约束

本文件约束 Agile 模式下负责工作执行的独立 subagent。

## 工作准备与边界

1. **先读 Plan 与 `<exec-rule>`**：开工前阅读调度者指定的 `summary.md`，聚焦当前 Stub 的范围、正式依据、验收要求、`<exec-rule>` 与补充约束。
2. **聚焦范围与职责**：仅在调度者分配的 Stub 与当前轮次范围内修改代码或文稿，不越界改动无关模块。不修改 `summary.md` 的 YAML 状态头，不修改已完成的历史 Plan 与交付记录。
3. **加载 principle**：开工前使用 principles skill 加载 `summary.md` 中适用于当前工作范围的原则（已读且仍适用的内容不必重读）。
4. **验证与目录清洁**：按验收标准运行必要验证，优先复用既有检查。调试探针、过程日志与中间临时数据统一放入项目根 `.tmp/`，不散落在源码或 Plan 目录；仅将通过验证的最终关键证据按需放入 `<Plan目录>/evidence/`。
5. **缺项上报**：若输入、正式依据或验收条件存在缺项，如实说明缺项、受影响部分与继续条件，继续完成不依赖缺项的部分或向调度者报告受阻。

## Stub 目录维护规范（`<Plan目录>/<StubID>/`）

开工时按需创建 `<Plan目录>/<StubID>/` 目录，开发 subagent 在其中仅维护 `result.md` 与按需创建的 `handoff.md`。真实产物本身即是成果证明，记录保持客观精炼：

### `result.md`（必填）

记录本 Stub 的最新交付物与验证依据，采用两段式结构：

```markdown
# S01 交付结果

## 产物清单

- `path/to/something`：[新增 | 修改 | 删除] 核心交付内容简述。

## 验证依据

- [自验手段]：执行命令与退出码 / 核查比对结果。
```

### `handoff.md`（按需）

仅写值得跨 Stub 重点关注的交接约定、接口签名、调用约束与未决限制；无特殊交接事项时**不创建**该文件。

```markdown
# S01 交接与遗留

## 交接约定

- **调用/使用入口**：下游 Stub 或使用方需要特别留意的接手点与约定。

## 未决与限制

- 本次未覆盖的边界、平台限制或待后续处理的遗留项。
```

### 写作与职责边界

1. **物先于言，拒绝流水账**：每项改动以真实文件路径或实体产物为锚点；不复述目标与背景，不写试探过程流水账，不使用“完美、优雅、大幅提升”等主观修饰词。
2. **交接收敛，控制体量**：`handoff.md` 宜控制在 **1,200 字以内**，代码实现或已有文档通过路径与锚点引用，不大段粘贴原文。
3. **原地更新，保持审核文件独立**：返工或后续推进时仅原地更新 `result.md`（及按需更新 `handoff.md`），反映本 Stub 当前最新交付状态；`stub-review.md` 与 `findings/` 由审核 subagent 独立维护，开发方不应修改、删除或覆盖。
