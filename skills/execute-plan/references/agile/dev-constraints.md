# Agile 开发 subagent 约束

本文件约束 Agile 模式下负责工作执行的独立 subagent。

## 工作准备与边界

1. **先读 Plan 与 `<exec-rule>`**：开工前阅读调度者指定的 `summary.md`，聚焦当前 Stub 的范围、正式依据、验收要求、`<exec-rule>` 与补充约束。
2. **严守范围与职责**：仅在调度者分配的 Stub 与当前轮次范围内修改代码或文稿，不越界改动无关模块。不修改 `summary.md` 的 YAML 状态头，不修改已完成的历史 Plan 与交付记录。
3. **加载 principle**：开工前使用 `handbook load <ID> [<ID> ...]` 加载 `summary.md` 中适用于本轮的 `principle` ID（已读且仍适用的内容不必重读）。执行中遇到未覆盖的语言规范、架构取舍或边界决策时，自主使用 `handbook list --kind principle` 与 `handbook load` 检索并加载相关原则。
4. **验证与目录清洁**：按验收标准运行必要验证，优先复用既有检查。调试探针、过程日志与中间临时数据一律放入项目根 `.tmp/`，不散落在源码或 Plan 目录；仅将通过验证的最终关键证据按需放入 `<Plan目录>/evidence/`。
5. **缺项上报**：若输入、正式依据或验收条件存在缺项，如实说明缺项、受影响部分与继续条件，继续完成不依赖缺项的部分或向调度者报告受阻。

## `Sxx-result.md` 维护规范

在调度者指定的路径（`<Plan目录>/<StubID>-result.md`）创建并维护交付区。真实产物本身即是成果证明，交付区保持客观精炼，采用三段式结构：

```markdown
# S01 交付与审核

## 产物清单

- `path/to/something`：[新增 | 修改 | 删除] 核心交付内容简述。

## 验证依据

- [自验手段]：执行命令与退出码 / 核查比对结果，关键证据按需归档于 `evidence/`。

## 交接与遗留

- **调用/使用入口**：对于工作下游或使用方需要特别留意的接手点。
- **未决与限制**：本次未覆盖的边界或遗留问题。
```

### 写作与分区铁律

1. **物先于言，拒绝流水账**：每项改动以真实文件路径或实体产物为锚点；不复述目标与背景，不写试探过程流水账，不使用“完美、优雅、大幅提升”等主观修饰词。
2. **原地更新交付区，严禁改写审核区**：上半区（`## 产物清单`、`## 验证依据`、`## 交接与遗留`）始终反映本 Stub 当前最新交付状态；返工或后续工作推进时仅原地更新上半区，**严禁修改、删减或覆盖**由审核 subagent 维护的 `## 审核记录` 章节及 `Rxx` 问题条目。
3. **交接收敛**：若产物内容形式足够清晰且无特殊交接事项，`交接与遗留` 章节直接填 `无`，不强行拼凑内容。
