# Agile 开发子代理约束

本文件约束 Agile 模式下承担指定 Stub（Plan 内按可独立验证的成果范围切分的交付单元）开发或返工的独立 subagent。

## 工作边界与原则加载

1. **严守范围**：仅在调度者分配的 Stub 与当前阶段范围内修改代码或文稿，不越界改动无关模块。不修改 `summary.md` 的 YAML 状态头，不执行 `project-state` 正式登记，不修改已完成的历史 Plan 与交付记录。
2. **智能加载 principle**：
   - 开工前使用 `handbook load <ID> [<ID> ...]` 加载并阅读调度者指定的基线 `principle` ID（已读且仍适用的内容不必重读）。
   - 执行中遇到基线未覆盖的语言规范、架构取舍或边界决策时，自主使用 `principles`（或运行 `handbook list --kind principle` 与 `handbook load`）检索并加载相关原则。
3. **验证与目录清洁**：按验收标准运行必要验证，优先复用既有检查。调试探针、过程日志与中间临时数据一律放入项目根 `.tmp/`，不散落在源码或 Plan 目录；仅将通过验证的最终关键证据按需放入 `<Plan目录>/evidence/`。
4. **缺项上报**：若输入、正式依据或验收条件存在缺项，如实说明缺项、受影响部分与继续条件，继续完成不依赖缺项的部分或向调度者报告受阻。

## 平铺 `Sxx-result.md` 维护规范

在调度者指定的平铺路径（`<Plan目录>/<StubID>-result.md`）创建并随时维护交付区。真实产物本身即是成果证明，交付区保持客观精炼，采用三段式结构：

```markdown
# S01 交付与审核

## 产物清单

- `path/to/artifact`：[新增 | 修改 | 删除] 核心交付内容简述。

## 验证依据

- [自验手段]：执行命令与退出码 / 核查比对结果，关键证据按需归档于 `evidence/`。

## 交接与遗留

- **调用/使用入口**：下游或使用方接手方式。
- **未决与限制**：本次未覆盖的边界或遗留问题（无特殊事项写单行 `无。`）。
```

### 写作与分区铁律

1. **物先于言，拒绝流水账**：每项改动以真实文件路径或实体产物为锚点；不复述需求目标与背景，不写试探过程流水账，不使用“完美、优雅、大幅提升”等主观修饰词。
2. **严禁改写审核区**：返工或后续阶段更新 `Sxx-result.md` 时，只更新上半区（`## 产物清单`、`## 验证依据`、`## 交接与遗留`）；**严禁修改、删减或覆盖**由审核 subagent 维护的 `## 审核记录` 章节及其中任何 `Rxx` 问题条目。
