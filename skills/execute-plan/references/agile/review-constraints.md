# Agile 审核 subagent 约束

本文件约束 Agile 模式下承担 Stub 审核或 Plan 总体终验的独立 subagent。

## 审核准备与职责

1. **先读 Plan 与 `<review-rule>`**：审核前阅读 `summary.md`，聚焦本次审核对象的范围、验收标准、`<review-rule>` 与补充约束。
2. **独立取证**：以真实代码、产物、运行回执与验收标准为裁决依据；`result.md` 与 `handoff.md` 仅作上次执行者的工作报告，不能替代真实证据。不修改业务代码、`result.md` 或 `handoff.md`，不更新 `summary.md` 状态头。
3. **加载 principle**：审核前使用 principles skill 加载 `summary.md` 中适用于本次审核的原则（已读且仍适用的内容不必重读）；也可自主尝试检索并加载相关原则。

## 两类审核的核对重点

- **Stub 审核**（维护 `<Plan目录>/<StubID>/stub-review.md`，有问题时在 `<Plan目录>/<StubID>/findings/` 下逐条建档）：仅针对当前 Stub 与当前审核轮次，核对是否严守范围边界、满足本 Stub 契约与 `<review-rule>`、遵守适用 `principle`、自验真实充分及目录清洁（无散落调试文件，探针均在项目根 `.tmp/`）；必要时独立重跑关键校验。Stub 审核不代替 Plan 总体终验。
- **Plan 总体终验**（维护 `<Plan目录>/review.md`，有跨 Stub 问题时在 `<Plan目录>/findings/` 下逐条建档）：面向整个 Plan 的最终交付，对照 `summary.md` 的工作内容、总体验收标准与补充约束，核实 Plan 总体目标完成度、所有 `Sxx/stub-review.md` 均已 `pass` 且无未闭环的 `open` 问题并且目录清洁。

## 裁决判据

- **`pass`**：满足全部交付约定、验收标准及目录清洁要求。
- **`rework`**：产物不符合约定、存在缺陷、缺少必要改动，或目录散落未清理的临时调试文件。
- **`inconclusive`**：审核所需输入、方法或验证环境缺失，导致无法形成确切判断（应写明缺项与受影响范围）。

## 写入格式与再审铁律

### 审核总览（`stub-review.md` / `review.md`）

- **Stub 审核**：写入 `<Plan目录>/<StubID>/stub-review.md`，标题为 `# <StubID> 审核记录`。
- **Plan 总体终验**：写入 `<Plan目录>/review.md`，标题为 `# Plan 总体终验`。

审核总览采用极简结构，严禁罗列阅读文件清单、过程流水账或在结论下堆叠多段叙事长文：

```markdown
# S01 审核记录

## 审核结论

- **[审核项] 结论**：`pass` | `rework` | `inconclusive`（YYYY-MM-DD）——[宏观判定理由，严格控制在 100 字以内，直截了当给出判断。]
  - **验证摘要**：[独立执行的校验范围、关键结果与未运行范围，限 1–2 句精炼陈述。]

## 问题索引

| 编号 | 状态 | 摘要 | 详情 |
| --- | --- | --- | --- |
| R01 | `open` | [简要问题名称] | `findings/R01.md`（写入时可用 Markdown 链接） |
```

无任何问题时，`## 问题索引` 下仅写单行 `无。`，不创建 `findings/` 目录。

### 独立问题文件（`findings/Rxx.md`）

每条阻碍项、缺陷或未决项在同级 `findings/` 目录下按 `R01.md`、`R02.md` 顺序独立建档，便于调度者定向派发返工：

```markdown
# R01 [简要问题名称]

- **状态**：`open` | `resolved`
- **位置**：`path/to/file:line`
- **要求**：验收标准、契约或 principle 的明确要求
- **证据与影响**：实际代码或运行证据，说明不合规点及影响
- **复验动态**：（初审可留空；返工复验时按日期追加最新核验结果）
```

### 编号与再审规则

1. **结论克制**：每条结论理由严格限制在 100 字以内；`验证摘要` 仅交代独立校验结果与未验范围，不写试探过程。
2. **问题原子化与顺延编号**：每条问题独立成文并按 `R01`、`R02` 顺延递增；同一 Stub（或 Plan 总体终验）跨轮次新增问题顺延递增，不重号。
3. **返工再审定向更新，严禁清空历史**：同轮次返工再审时，仅更新本轮涉及的 `findings/Rxx.md`（更新状态并追加 `复验动态`），并在审核总览中同步更新对应结论行与 `## 问题索引` 状态，不改动其他已关闭的问题文件；同一 Stub 存在多个独立审核轮次时，在 `## 审核结论` 下按时间顺序追加新结论项。
