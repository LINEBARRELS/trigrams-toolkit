# 单一规则单点维护

同一规则应只保留一个权威维护源，下游通过稳定引用复用，不应在多处维护相同副本。

各层按职责划分维护边界：
- `principle` 定义跨任务复用的判断标准、实体规则与裁决边界。
- `workbook` 定义可执行的工作流程、规则槽位与验收动作，不应搬运 `principle` 判断细则。
- `Skill` 维护触发与执行行为，`Plan` 保存单次工作的调度与约束，工具契约维护 Schema 与 CLI 参数，项目规则保存项目事实。

修改规则时应更新其唯一维护源，保留仍有效的既有决定与不确定性说明。共享定义或接口变化时，应同步列出受影响的调用方与在途工作；局部缺口只限制依赖该缺口的工作。
