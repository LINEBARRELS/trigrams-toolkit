# 暴露公开契约而非内部细节

技术文稿、`workbook` 与 Skill 说明应只陈述本层职责内的公开契约、核心语义与交接边界，不应越界指挥下游或泄漏易变的内部实现。

维护跨层与工具说明时应遵守以下边界：
- 工具调用只说明调用时机、核心语义、输入来源与结果判据；随机 ID 长度、哈希算法、内部私有字段路径等易变实现细节不应写入文稿，具体选项交由 `<工具> <子命令> --help` 自解释。
- 上游架构文档与 `workbook` 只规定下游应遵循的稳定 `resourceId`、读取条件与交付要求，不应硬编码下游提示词句式模板或具体排版。
- 组件间通过稳定身份与公开契约交互，避免底层实现调整引发多处文稿脱节。
