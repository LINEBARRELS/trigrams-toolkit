# 正向陈述确定规则并剔除防御套话

文稿与规则应正向陈述已确定的事实、期望行为与可验证的验收条件，做到如无必要、勿增实体。

起草或修订正文时应满足以下要求：
- 强制要求应有用户决定、正式规则、接口契约或可证实的失败风险作为依据；固定顺序仅用于真实依赖，示例只解释方法与格式，不应将示例的数量、篇幅或步骤升格为强制规定。
- 只记录当前必需的约束，不应预设空目录、占位字段或假设性限制。
- 将“不应把 X 当 Y”等防御禁令改写为对正确做法与边界的明确声明；剔除缺乏上下文信息的常识套话。
- 中文正文遵循 `doc-polish` 语言规范，保持一词一义与段首结论。
