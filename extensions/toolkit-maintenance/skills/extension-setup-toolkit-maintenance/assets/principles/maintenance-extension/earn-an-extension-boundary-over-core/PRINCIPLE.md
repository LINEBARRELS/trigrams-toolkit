# 扩展与扩展 workbook 应以独立领域边界赢得设立资格

新建扩展或新增扩展 `workbook` 应以真实存在的独立领域生命周期为前提；可由 core 通用能力与 `principle` 覆盖的场景，不应增设冗余包装。

决策边界划分时应遵循以下判据：
- 跨领域通用的开发、文档、计划、代码规范与底座接入能力归属 core；仅当存在独立领域工作周期、专属 `<extension>:*` 工件与关系，或成体系的跨任务领域判据时，才设立独立扩展。
- 扩展内仅将具备固定工序、硬性门禁或独特协作节奏的流程固化为 `workbook`；单类材料的判断标准与日常约束应沉淀为按需检索的 `principle`。
- 不应设立只负责列举 `handbook list`/`load` 路由表或套用通用审核话术的空壳 `workbook`，防止入口碎片化与维护失焦。
