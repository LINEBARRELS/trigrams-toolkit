# 保持 Skill 职责内聚与跨能力显式组合

Skill 应专注本职交付，隔离通用流程与领域规则，并通过显式契约组合其他能力。

编写或审核 Skill 正文时应遵循以下规范：
- 通用 Skill、通用角色与宿主入口只维护跨领域的输入、交付、依赖、状态与协议；专业方法、领域身份与验收标准应按需从适用的 `workbook` 或 `principle` 加载，审核通用入口时应使用不同领域的代表性工作检验完整性。
- Skill 相互调用仅在必须时明确的声明，且使用 Agent harness 标准的 Skill 调用方式，避免因对其他 Skill 的冗余描述而触发不必要的隐式调用，且不应直接读取其他 Skill 的私有文件。
- 正文直接描述工作动作、条件与结果，默认省略执行主体称谓；仅在授权、调度、交接等需要明确执行主体的地方时写明执行主体，不在同一责任范围内反复补写称谓，例如 “用户” “开发者” “Agent”。
