# 按独立交付结果与真实依赖切分工序及 Stub 交接

`workbook` 中的工序切分应保持 Plan 模式中立，以可独立交付、可独立验收的结果为边界，不强制套用固定阶段数量，也不硬编码特定 Plan 模式的调度字段。

工序依赖与 Stub 交接应遵循以下判断：
- 下游工序需要消费上游完整成果（如整改依赖完整审核结论、复验依赖整改后的实际产物）时，明确先后依赖与交接物。
- `Stub` 是 Plan 内通用的工作范围边界或关键交付单元；`workbook` 应说明如何按工作目标、成果结构与现状划定 Stub 范围及交接位置。
- 仅在领域确实需要分阶段验收时（如编程框架安装与逻辑装填），在 `workbook` 中写明多阶段审核检查点与各阶段必读原则，由 `to-plan` 在规划阶段固化进 Plan 正文。
