# 按独立交付结果与真实依赖切分 Task 及 Stub 交接

`workbook` 中的任务切分应以可独立交付、可独立验收的结果为边界，不强制套用固定的任务数量或三段式模板。

任务依赖与阶段交接应遵循以下判断：
- 下游任务需要消费上游完整成果（如整改依赖完整审核结论、复验依赖整改后的实际产物）时，应使用显式 `dependsOn` 表达先后依赖。
- 围绕核心工作定义 `Stub`，按工作目标、成果结构和现状确定范围。`Stub` 的完整定义与交接要求维护在 `Plan` 的 `summary.md` 中，`Task` 仅声明编号与名称。
- 同一个 `Stub` 应由不同 `Task` 先后负责安装（`installs`）与装填（`fills`）；声明 `uses` 的下游任务仅等待安装完成，不代表完整成果已就绪。
