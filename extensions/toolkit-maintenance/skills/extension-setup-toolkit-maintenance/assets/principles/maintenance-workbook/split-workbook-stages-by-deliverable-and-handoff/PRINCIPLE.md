# 按独立交付结果与真实依赖切分工序及交接

`WORKBOOK.md` 的工序切分应保持 Plan 模式中立，以可独立交付、可独立验收的工作交付单元为边界，不预设固定的工作阶段。

设计工序与交接时应遵循以下判断：
- 沿用模式中立的 `Stub` 表达通用工作范围或交付边界，不写入 `Task`、`task.md`、`summary.md`、`plan.json` 等特定模式概念或“由 `to-plan` 固化进 Plan”等规划实现操作。
- 仅在下游确实消费上游完整成果（如整改依赖完整审核结论、复验依赖实际产物）时声明前后依赖与交接物。
- 仅当下游存在真实的前置契约阻塞依赖（如编程框架骨架先于逻辑实现）时，才拆分多阶段交接并明确各阶段审核门禁；不应为对齐其他领域模板而硬拆阶段。
