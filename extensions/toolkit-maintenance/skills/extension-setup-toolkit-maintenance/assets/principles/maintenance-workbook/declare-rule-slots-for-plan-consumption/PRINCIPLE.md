# 按消费角色声明规则槽位并审慎使用条件分支

当 `WORKBOOK.md` 中存在关键的、需要稳定地被装填到 Plan 中的特定类型规则，或需要编写仅在特定条件生效的规则时，按照类型与规则的下游消费者（schedule - 调度者、exec - 执行者、review - 审核人）使用 xml 标签对规则内容进行封装。

编排规则槽位时应遵守以下约定：
- `<schedule-rule>` 承载调度分类、协同路由与推进节奏；`<exec-rule>` 承载执行动作、必经门禁与按需原则加载触发；`<review-rule>` 承载独立审核范围、必读审校原则与否决条件。
- 默认使用无条件属性的标签直接包裹规则；当需要针对**拥有某些特征**的工作做差异化的调度、执行或审核规则要求时，使用相邻的非嵌套同名标签附带 `if` / `else-if` / `else` 属性，构成互斥条件组，不为套用语法而硬造分支。
  - 条件内容使用自然语言简短描述；避免编写过于复杂、难以判定的条件。
